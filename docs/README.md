## 決定事項（2026-10-20）

- **名古屋を先に作る**（決定）。
- 表示言語は日本語のみ（英語は構造だけ用意）。
- 通貨は万円表示（内部値 ×1000、[01 §3.10]）。
- 未決: ゲーム名とロゴ（[01 §6.1] に方向性の案）。

## 結論（推奨の理由）

**名古屋を先に作る。** 規模（87 駅・6 路線・6 時代）が元ゲームの調整済み経済に近く、事業者が一つで「一時代＝一路線」の型にはまり、名古屋に必要なエンジン追加（環状線・既存駅を経由するコリドー）は東京でもそのまま使える。東京は 216 駅・13 路線・2 事業者で、時代数と経済の指数を変えた上で計測し直す必要があり、パック化を名古屋で証明してから取り組むのが安全。理由の詳細は [01 §0.3](01-spec-engine-city-pack.md#03-推奨順序結論)。

## 実装の進め方（要約）

1. **M0 パック化**: `src/data.js` と `src/facts.js` を `src/city/<id>/` に移し、エンジンから都市名を消す。ストックホルムもパックとして残し、既存の `node _dev/smoke.mjs` / `node _dev/value-gate.mjs` を緑のまま保つ。名古屋パックのデータ投入と日本語 UI。
2. **M1 環状線**（名城線）。
3. **M2 土地の味**: 直通運転、手書き路線図、黄電、日本語フォント、UI 提案。
4. **M3 計測と調整**: `_dev/probe-arc.mjs` で時代ゲートを直す。
5. **M4 東京**。

各段階の完了条件は [01 §7](01-spec-engine-city-pack.md#7-マイルストーン)。

## オーナーが決めること

- ゲーム名とロゴ（「Tunnelbana」の名前・ロゴ・アートワークは MIT の対象外。[01 §0.4]）。候補は [01 §6](01-spec-engine-city-pack.md#6-名前言葉の決め事オーナー判断が必要なもの)。
- 表示言語（日本語のみ／日本語＋英語）。
- 通貨の表示倍率（内部値 ×1000 を円で表示する案、[01 §3.10]）。
- （名古屋のラインカラーは DIC 番号で確定済み。[02 §3]。東京は M4 で確定）

## 史実の確認状況

歴史文書は Web 検索で収集し、2 系統以上で一致したものを「確認済」、1 系統のみ・食い違いありを「要確認」と明記している（推測で埋めた箇所は無い）。2 回目の調査で、名古屋の開業日（高畑・上社・久屋大通）とラインカラー（DIC 番号）、東京の後年追加駅・大江戸線・半蔵門線・新宿線直通の日付は裏取り済み。残る未確認は、名城線 市役所〜大曽根（国交省一覧のみ）、日比谷線 恵比寿〜中目黒 1964-07-22、東京の 9 路線分のラインカラー HEX、虎ノ門ヒルズの座標。各文書の冒頭「追加調査」に出典を記した。
